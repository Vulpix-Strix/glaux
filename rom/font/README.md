# System font

The System ROM font is [Pixel Code](https://qwerasd205.github.io/PixelCode/)
Regular by Qwerasd, built at load time from the 1-bit glyph drawings its own
build compiles into outline fonts. The files in `pixel-code/` come from
<https://github.com/qwerasd205/PixelCode> at commit
`eefe4180f376b5bd9a9d3c39f1fca6956fdbb702`, directory `src/glyphs/`.
`LICENSE-PixelCode` is the repository's `LICENSE` (SIL Open Font License 1.1),
copied unmodified.

Every glyph sits in a 6×12 cell, or two cells for the double-width dingbats.
The font covers the same 1,792 codepoints as the compiled `PixelCode.ttf`.

## Files

The PNGs are unmodified. Some are renamed, because upstream names contain
characters Windows does not allow in file names:

- `*.png` at the top level: the codepoint atlases, named after their range.
  `2700-27BF@2X.png` draws the dingbats at twice the resolution; Glaux uses
  it only where `2700-27BF.png` is blank, and reduces it to 6×12 by inking a
  pixel wherever any of its four half-pixels is inked.
- `_.notdef.png`: the glyph shown for characters the font lacks.
- `ligatures/`: one drawing per programming ligature, one cell per
  character. Upstream names them by their text in quotes, such as `"->".png`;
  here each character is spelled by its glyph name and joined with `_`, as
  upstream already does for a few (`hyphen_greater.png`). A `.lazy` suffix
  stands for upstream's trailing `?`: the ligature only forms between spaces.
- `calt/`, `onum/`, `ss01/`, `ss20/`: alternate glyphs from upstream's
  `+calt/`, `+onum/`, `+ss01/` and `+shifted/`, named after the codepoint they
  replace. `+shifted/` holds the `ss20` (pseudo-kerning) alternate.
- `features/`: the OpenType feature files these alternates and ligatures
  come with, kept as the reference for the substitution rules
  `apps/glaux/src/rom/pixel_code.rs` ports.

Upstream's other weights and italics are generated by thickening and
slanting outlines, so they do not land on whole pixels and are not used.
